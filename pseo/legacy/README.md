# legacy — отменённая схема, НЕ ТРОГАТЬ

Здесь лежит код тракта, отменённого каноном §0.19 (2026-08-20): рты `facet`, `carve`,
`assign`, `deals`, вопрос-контур, тупиковый `page_builder`. Он ничего не запускает: пульт
его не зовёт, живые модули на него не ссылаются.

⛔ **Правила:**

- **не править** — правки сюда бессмысленны, код не бежит;
- **не оживлять** — если кажется, что нужно, значит нужно звено нового тракта, а не это;
- **читать можно** и иногда полезно: 24.08 отсюда взяты промпты `DEALS_SYS` и
  `DEAL_ASSIGN_SYS` — готовые формулировки закрытого списка, вместо выдуманных заново.
  Но берётся ФОРМУЛИРОВКА, а не приём: пачки, пороги и имена решает `PLAN.md`.

Зачем вынесено: пока живое и мёртвое лежали в одной папке, каждое обращение к трём нужным
функциям открывало файл на 1 292 строки со старыми приёмами перед глазами — и они
переносились в новый код по привычке (пачки по 90 вместо одного вызова на тему, вторая
транслитерация рядом со `slugs.py`). Чтение корпуса теперь в `builder/corpus.py`, вектора —
в `builder/vectors.py`.

⛔ **Доки отсюда НЕ переносить в `PLAN.md`** (заказ юзера 25.08). Перенос строк из архива
уже дал противоречие: «части внутри страницы, адрес один» против «страница не больше 15
абзацев». `PLAN.md` пишется из решений юзера и замеров, а не цитатами из снесённой схемы.

`BUILDER_RULES.md` — старый канон: часть правил жива, но лежит вперемешку с отменёнными, и
разделять их построчно дороже, чем записать нужное заново в `PLAN.md`.
`SITE_MAP.md` — описание ВЫЛОЖЕННОГО старого сайта (мостик `/s/`, разборы, ветки), 14.08.

История цела: файлы переехали через `git mv`, `git log --follow` работает.
