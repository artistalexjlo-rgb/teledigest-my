## ПОЛНЫЙ СТЕК (от мухи до прода; «процессов вне этой схемы не существует»)

```text
ПОСТОЯННО (реестр ниже):
  бот bots-grab (docker) ── граббер чатов → SQLite
       └─ экстрактор: сообщения → мухи ai_lesson   [Gemini flash-lite, учёт gemini_quota]
       └─ embed → Qdrant                            [gemini-embedding-2, свой RPD]

  sentinel (cron /6ч) ── HTTP-сторож портала, чирик при поломке [без Gemini]

ПО ОТМАШКЕ (кнопка пульта, один прогон, умирает по завершении) — тракт `pseo/docs/PLAN.md`:
  2. tract.py <geo> --collapse    схлопывание почти-копий, порог 0.93   [ключей НЕТ]
  3. tract.py <geo> --mark        тема из 13 + подтема, по-английски    [рот mark]
  4. tract.py <geo> --summarize   проход А (имена) + проход Б (раскладка) [рты canon, assign]
  5. tract.py <geo> --build       корпус по справочнику                 [ключей НЕТ]
  5. site.py --all                корпус → страницы дерева              [ключей НЕТ]
     render.py --all              страницы → HTML                       [ключей НЕТ]
  6. translation.py <geo>         13 языков, английский копией          [рты translate, labels]
  7. публикация                   ЗВЕНО НЕ НАПИСАНО (кнопки нет)
```

⚠️ **Публикации сейчас нет.** Старый путь (`ship.py` = pull → `pages.py` → render → гейт →
push в Cloudflare Pages) снят 27.08 вместе со старым сборщиком: дерево он строил отменённое,
а CF Pages и так отвергал деплой (потолок 20 000 файлов при 41 630 страницах). Сайт живёт
снимком, отдаёт его `bots-pseosite` из `/root/pseo_builder/site/online`.

Все Gemini-вызовы билдера — ТОЛЬКО через `keybroker.call`, и список имён ЗАКРЫТ: `mark` 1500 ·
`canon` 300 · `assign` 300 · `translate` 400 · `labels` 200 · `extract` 300. Незнакомое имя мозг
отвергает. Поверх — per-key шаг/RPD и вина-vs-среда; мимо мозга запросов не существует.

**Правило (2026-07-20, после инцидента pseo-runner):** на VPS имеет право жить ТОЛЬКО то,
что есть в этой таблице. Новый юнит/таймер/крон = явное «да» юзера + строка здесь В ТОМ ЖЕ
заходе. Всё, чего в таблице нет, — сносится при первой сверке. Сверка (`systemctl
list-timers`, `crontab -l`, running services) — в начале каждой рабочей сессии.

**Контекст инцидента:** юнит `pseo-runner.service` (авто-тегание, «удобная автоматика»)
был заведён 6 июля вне git и вне доков, пережил все уборки и три недели молотил ключи,
пока юзер считал, что «ничего не работает». 2026-07-19 он выел 1764 гранта за день и
устроил 429-фон. Самоходных демонов у билдера НЕ СУЩЕСТВУЕТ КАК КЛАССА: весь тракт
(схлопывание → разметка → обобщение → сборка → переводы → публикация) — по отмашке.

## ПУБЛИКАЦИЯ БЕЗ АССИСТЕНТА — принятая схема (2026-08-10)

**СТАТУС на 2026-08-11: отдача РАБОТАЕТ, публикации ещё НЕТ.** Читать как задание в той
части, что помечена «осталось». Заказ юзера дословно: «мне нужен путь работающий без тебя,
готовый, не процесс кодирования».

Сделано и проверено фактом:

- шаг 1 — рендер-половина едет в образ пульта (ветка `feat/pult-render-half`), копий в git
  не появилось: контекст сборки переносится в корень репо;
- приложение **`bots-pseosite`** заведено юзером и поднято: `nginx:alpine`, реплики 1/1,
  bind `/root/pseo_builder/site/online` → `/usr/share/nginx/html`, лимит 256 МиБ, роутер
  Traefik на `info.multyspeak.online`. Проверка с самого сервера: `http` → 301,
  `https` → 200, отдаётся файл из хостового каталога.
  ⚠️ Сертификат пока self-signed — Let's Encrypt не подтвердит домен, пока DNS смотрит на
  Cloudflare Pages. Лечится переключением DNS, кода не касается.

Осталось: `PSEO_OUT` одним источником, `publish.py`, шаг «Публикация» в пульте, правка двух
полей сборки пульта в панели, DNS.

**Состояние на 27.08.** Рендер-половина в образе пульта УЖЕ есть: `render.py`, `site.py`,
`translation.py`, `templates/`, `i18n/`, `static/`, `config/`. Не хватает последнего шага —
самой публикации: старый `ship.py` снят вместе со старым сборщиком, нового нет.

**Целевая схема — кнопка в Телеграме:**

- сайт = **каталог на диске хоста** `/root/pseo_builder/site/<домен>/`, ВНЕ контейнеров:
  редеплой любого приложения страниц не касается.
  ⭐ Каталог лежит ВНУТРИ уже примонтированного мозга (`/root/pseo_builder`, RW) — это
  замечание юзера «а у нас там уже есть такие». Пульту новый маунт не нужен вовсе, путь
  берётся из существующей `BRAIN_DIR`, новых настроек не появляется. Бэкапер эту папку не
  берёт (у него перечислены `out_facet*`, `tags`, `keybroker.db`) — и правильно, сайт
  восстанавливается рендером;
- **пульт** (`bots-luky-rodzkl`) получает рендер-половину и шаг «Публикация» в
  `pipeline_steps()`; пишет в тот же примонтированный мозг;
- **новое приложение Dokploy**: Source Type `Docker`, образ `nginx:alpine`, тот же каталог
  на чтение, домен `info.multyspeak.online`, порт 80, лимит памяти. Сборки у этого
  провайдера нет — задавать нечего;
- оба домена = ДВА прогона одного рендера с разными `PSEO_DOMAIN` / `PSEO_CTA_URL` в разные
  каталоги (переменные уже есть, копий логики не нужно);
- рендер пишет в ЧЕРНОВИК рядом, затем `rsync -a --delete` черновик → отдаваемый каталог.
  ⛔ Переименовать каталог НЕЛЬЗЯ, хотя так и было записано сперва: bind-маунт разрешается
  при старте контейнера, и после переименования nginx продолжит отдавать старый, уже
  отвязанный каталог. Отдаваемый каталог обязан сохранять свой inode. Рендер — минуты,
  `rsync` — секунды, окно несогласованности сжимается до них. `rsync` нужен в образе
  (в `python:3.12-slim` его нет);
- `PSEO_OUT` — новая переменная каталога вывода в `render.py` (одна строка), чтобы писать
  сразу в маунт, а не копировать после;
- git остаётся **историей и бэкапом, не транспортом**: `step_pull`, `_pull_mature`,
  `step_push` в схеме не участвуют. Cloudflare — только DNS и кеш.

**Островков всего три:** каталог, приложение nginx, запись DNS.

**Чего НЕ делать (перечислено, чтобы не выдумывалось заново):**

- не собирать Docker-образ из корпуса — именно это положило РФ-сервер 2026-08-09 вместе с
  ВПН, переводчиком, инфо-порталом и БД. Ложится сборка, не отдача;
- не совмещать сайт и пульт в одном контейнере: рестарт бота гасил бы сайт, и наружу
  смотрел бы контейнер с ключами Gemini. Юзер этого и не просил;
- не заводить хостовых скриптов, systemd-юнитов и крона — реестр выше это запрещает;
- не тащить релизы, симлинки, `--link-dest` и nginx-`map`: отброшено как страховка от
  проблем, которых у нас нет.

**Порядок работ (по коммитам, каждый — ветка и PR):**

1. перенос рендер-половины в `pseo/combine/` + `jinja2` в `requirements.txt` + фикстура
   «в образе есть всё, что нужно рендеру»;
2. публикация в комбайне: `site.py --all` → `render.py --all` → `readycheck` как гейт →
   каталог отдачи → сводка числами;
3. шаг «Публикация» в `pipeline_steps` (одно место: оттуда и кнопка, и цепочка) + сторожа:
   пишет в маунт а не в `/app`, два рендера с разными доменами в разные каталоги, нет
   корпуса — шаг молчит а не падает, каталог равен корпусу — шаг не зовёт;
4. README комбайна: новый Directory Mount и лимит памяти точными полями.

**Руки юзера, однажды:** приложение nginx с одним маунтом (СДЕЛАНО 11.08), два поля сборки
пульта — `Build Path` `/` и `Docker File` `pseo/combine/Dockerfile` (после мёржа шага 1),
запись DNS. Дальше — только кнопка.

**Открыто:** 996 редиректов из `_redirects` — это фича Pages, на nginx не работают, решать
отдельным заходом. Лимит памяти пульту ставить ПОСЛЕ первого замера рендера в контейнере —
замера нет, наугад не ставить.
