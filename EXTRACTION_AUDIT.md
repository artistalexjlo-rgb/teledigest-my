## Вопросы (по весу)

### 1. Пустые файлы крутятся вечно

`.processed` ставится только при `attempted > 0` (`run_extraction_pass`). Ноль паттернов →
файл не помечен → в очередь снова завтра. 241 файл «сообщений нет» ежедневно съедают вызов,
ключ и 4.5 с паузы. **Предложение:** пустой результат помечать отдельным сайдкаром `.empty`.

### 2. Большие файлы не проходят никогда

Таймаут 60 с захардкожен в `_gemini_generate_json`. Файлы от ~140 КБ (`cn`, `id/balichat`,
до 310 КБ) → 4 таймаута подряд, 5 минут, «failed after retries», завтра то же. Самые живые
чаты теряются целыми днями. **Предложение:** резать по порогу (~60 КБ) на куски, звать по
куску; id паттерна детерминирован по файлу и сквозному индексу — коллизий нет.

### 3. 429 = бан ключа на сутки, хотя это минутное окно

Все 34 отказа 429 — в первые полтора часа прохода, когда 12 ключей молотят подряд. Тело
ответа немое (`Resource has been exhausted`), код банит пару ключ-модель до полуночи
после 2–3 вызовов при капе 500. Пул 12 ключей на бумаге — треть по факту.
**Решение юзера 15.09:** не чинить на месте, а перевести экстрактор на мозг
(`pseo/tract/keybroker.py`): там лестница отдыха 60/300/1800/6000 с и дневной бан только
после полной лестницы, такт выдачи по живым ключам, роль `primary` для экстрактора, имя
`extract` в закрытом реестре уже заведено (cap 300). Открытые вопросы — ниже, §«Перевод
на мозг».

### 4. Кап RPD 20 для `2.5-flash` / `2.5-flash-lite` — откуда

В `_MINING_MODELS` без ссылки на факт. В мозге `LIMITS` проверены по скрину AI Studio
2026-07-14 (те же 20). При переводе на мозг таблица экстрактора уходит, остаётся одна.

### 5. Проход держит поток 1.5–2 часа

Файлы по одному, `_INTER_FILE_PAUSE_S`=4.5, `_INTER_MODEL_SLEEP_S`=60, ретраи 5+20+60.
Сам код помечает паузу к сносу при переводе на мозг (такт выдачи заменяет её).

### 6. Дубли в базе знаний

688 одинаковых title+country в `wisdom_base`. Дедуп по id защищает от повторной обработки
ТОГО ЖЕ файла, не от того же факта в разные дни. Тракт сайта схлопывает векторами (0.93),
помощник Luky ходит в Qdrant напрямую и видит все копии. **Вопрос:** дедуп на входе в
Qdrant (embed_pump), не в экстракторе?

### 7. Заголовки в двух стилях

`yellow_fever_vaccination_requirements` и `Currency exchange in Seoul` от одной модели —
промпт не задаёт формат `title`. Мелочь, по нему группируют.

### 8. Очередь историй без потребителя

25 926 историй, опубликовано 1 988. Экстрактор продолжает генерировать `human_story`
(токены, место в ответе) для очереди, которую канал забирает на 8 %. **Вопрос:** нужны ли
истории вообще; если да — кто и как их выбирает.

### 9. «Модель вернула мусор» ≠ «модель вернула пусто»

JSON-парс падает 4 раза за 48 ч → сейчас «0 patterns» → файл в очереди (см. §1). После
починки §1 такой файл пометится пустым и потеряется. Мозг уже считает непарсящееся тело
неудачей с повтором (`_BadShape`, `salvage`) — при переводе решается само.

### 10. Страны через запятую

1 669 мух вида `de, ru` (промпт разрешает). Тракт сайта раскладывает через `geo_codes`;
помощник фильтрует по `country` строкой. **Вопрос:** раскладывать в несколько строк на
входе в Qdrant? Не проверял `embed_pump`.

### 11. Тесты не покрывают поток файлов

`tests/test_extraction.py` — только ротатор и junk-фильтр. Сайдкар, ретраи, таймаут,
чанкинг — без сторожей. Пункты 1, 2, 9 без тестов повторятся.

Работает, трогать не надо: IPv4-фильтр, откат модели по 503, учёт «запрос не ушёл»,
детерминированный junk-guard `ai_lesson` (с тестами).

## Перевод на мозг (§3) — что надо решить до кода

Факты из `keybroker.py`: `call(user, sysprompt, consumer, model, role, timeout, salvage)`
→ dict | None; ключи рот не видит; своя БД `KB_DB=/root/pseo_builder/keybroker.db`;
`get_keys()` читает ключи сам; учёт по PT-дню; в докстринге TODO «подмешивать расход
экстрактора из `gemini_quota`» — при переводе он снимается сам: учёт один.

1. **Где живёт мозг для бота.** Сейчас `keybroker.py` лежит в `pseo/tract/`, бот —
   `src/teledigest/`, это ДВА разных контейнера (`bots-grab` и пульт). Общая БД
   `keybroker.db` на `/root/pseo_builder` — у `bots-grab` этот маунт есть? (у пульта есть).
   Варианты: (а) модуль копируется в образ бота и пишет в ту же SQLite по маунту;
   (б) выносится в общий пакет. Копия — второй экземпляр кода, расходятся за неделю.
2. **Один PT-день на двоих.** Экстрактор бежит ночью после дайджеста, пульт — по кнопке
   днём. Роль `primary` даёт экстрактору полный RPD, `background` — RPD минус RESERVE=60.
   Хватает ли 60 на ночь экстрактора при 286 файлах? Замер в докстринге «~22/ключ/ночь»
   старый.
3. **Порядок моделей.** Экстрактор ходит по трём моделям (`3.1-flash-lite` → `2.5-flash`
   → `2.5-flash-lite`), мозг — одна модель на вызов. Кто выбирает следующую модель, когда
   `acquire` вернул -1 (бюджет модели выбран): экстрактор сам перебирает список?
4. **Таймаут и чанкинг (§2)** — параметр `timeout` в `call` есть; резать файл — на стороне
   экстрактора до вызова.
5. **Ротатор и `gemini_quota` в боте** уходят целиком (`iter_model_key_pairs`,
   `quota_*`, тесты ротатора) — или остаются как fallback? Два учёта = два разных ответа
   на «ключи кончились».
6. **`salvage`** — экстрактору нужен `{"patterns": [...]}`; `salvage_objects` умеет
   вытаскивать объекты из битого JSON — включать?
